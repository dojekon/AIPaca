# AiPaca profiles repo — шаблон публикации

Репозиторий с профилями запуска моделей для приложения AiPaca. Приложение скачивает
`index.json` и все файлы, на которые он ссылается, кэширует их в Room (ETag) и объединяет
с профилями, вшитыми в APK.

Структура:

- `index.json` — каталог: список устройств (`devices`) и профилей (`profiles`)
- `devices/*.json` — спецификации устройств (SoC, RAM, cores, cpuMasks)
- `profiles/*.json` — профили запуска (backend, launch-параметры, sampling)
- `schema/v1.schema.json` — JSON-схема всех трёх типов документов

## Публикация

1. Форкните этот репозиторий на GitHub или скопируйте его содержимое на любой
   HTTP-хостинг (CORS не требуется, если это другой хост, приложение работает по обычному GET).
2. Изменения держите в ветке `main` (для GitHub-ссылки ветка по умолчанию — `main`).
3. В настройках приложения («Источник профилей») укажите URL:

   - `https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПО` — приложение само заменит его на
     `https://raw.githubusercontent.com/ВАШ_ЛОГИН/ВАШ_РЕПО/main/`;
   - либо сразу raw-префикс `https://raw.githubusercontent.com/ВАШ_ЛОГИН/ВАШ_РЕПО/main/`;
   - либо базовый URL своего хостинга, например `https://profiles.example.com/base/`.

4. Нажмите «Обновить» в приложении. Повторные обновления скачивают только изменившиеся
   файлы (сравнение по ETag).

## Как добавить свой профиль

1. Добавьте файл в `profiles/` (проще всего скопировать существующий). Поле
   `schemaVersion` должно быть равно `1`; допустимые backend: `cpu`, `opencl`, `hexagon`
   (профили `hexagon` используются приложением только при выбранном ускорителе NPU).
2. Зарегистрируйте файл в `index.json` — элемент массива `profiles`:

   ```json
   {
     "id": "my-model/q4_0/my-device",
     "family": "my-model",
     "device": "qcom-sm8650/12gb",
     "quants": ["Q4_0"],
     "file": "profiles/my-model-q4_0-sm8650.json"
   }
   ```

3. Для нового устройства добавьте файл в `devices/` и элемент массива `devices`
   в `index.json` (`key`, `soc`, `vendor`, `ramGb`, `file`).

Полное описание полей — в `schema/v1.schema.json`.

Профили из репозитория имеют меньший приоритет, чем вшитые в приложение: при совпадении
`id` или пути файла профиль из репозитория игнорируется.
